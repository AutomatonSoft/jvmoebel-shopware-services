# Тесты AR-моделей

Тесты service-слоя проверяют основные сценарии работы с AR-моделями: создание, получение, замену, удаление, изменение статуса, обработку отсутствующих моделей, уникальность SKU и конвертацию размеров в метры.

## Что тестируется

1. **Создание модели**
   - создаётся запись в БД;
   - сохраняется SKU, формат и статус;
   - размеры сохраняются в метрах;
   - файл физически сохраняется в storage.

2. **Конвертация размеров**
   Параметризованный тест проверяет:
   - `2 m → 2 m`;
   - `200 cm → 2 m`;
   - `2000 mm → 2 m`.

3. **Запрет дублирования SKU**
   - создаётся модель для `ABC-123`;
   - выполняется повторное создание;
   - ожидается `ARModelAlreadyExistsException`.

4. **Получение модели**
   - создаётся модель;
   - модель запрашивается через `service.get_model()`;
   - проверяется корректность возвращённых данных.

5. **Модель отсутствует**
   - запрашивается несуществующий SKU;
   - ожидается `None`.

6. **Модель отключена**
   - создаётся модель;
   - статус меняется на `not_active`;
   - `get_model()` больше не возвращает модель.

7. **Замена модели**
   - создаётся первоначальная модель;
   - загружается новая модель;
   - проверяются новые размеры и путь к файлу;
   - проверяется удаление старого файла.

8. **Замена несуществующей модели**
   - выполняется обновление неизвестного SKU;
   - ожидается `ARModelNotFoundException`.

9. **Изменение статуса**
   - статус модели изменяется с `active` на `not_active`;
   - проверяется новый статус.

10. **Изменение статуса несуществующей модели**
    - для неизвестного SKU ожидается `ARModelNotFoundException`.

11. **Удаление модели**
    - создаётся модель;
    - модель удаляется;
    - проверяется, что она больше не находится;
    - проверяется удаление физического файла.

12. **Удаление несуществующей модели**
    - для неизвестного SKU ожидается `ARModelNotFoundException`.

## Изоляция тестов

Для тестов используется отдельная PostgreSQL БД.

Перед каждым тестом:

- таблицы удаляются и создаются заново;
- используется отдельная SQLAlchemy-сессия;
- файлы сохраняются во временную директорию `tmp_path`;
- настоящий storage проекта не используется;
- валидатор GLB/USDZ заменяется mock-функцией.
